# 法源核對

筆記是逐字稿改寫來的，條號聽錯、記錯是這種材料的常態缺陷。錯的條號讀起來完全正常，
只有把條文原文調出來擺在旁邊才看得出來——所以這件事得靠機器逐條對，不能靠讀。

## 依據

`_Material/法源/個別法源PDF/` 本來就有 53 份法源 PDF，但 PDF 沒辦法 grep。
`scripts/build-statute-text.py` 用 `pdftotext -layout` 把它們抽成純文字，放進
`_Material/法源/個別法源文字/`（52 份、2.6 MB，跟 PDF 同名同分類）。

`-layout` 是必要的：法條 PDF 的項號（1、2、3）排在左欄，不保留版面就會跟內文黏在
一起，項次會判斷錯。

## 工具

```
python3 scripts/lookup-article.py 民法 761 --項 3     # 查單條
python3 scripts/lookup-article.py --scan <成稿.md>    # 一份檔的所有引用逐條列首句
python3 scripts/lookup-article.py --scan-all          # 全站，只列對不上的
python3 scripts/lookup-article.py --list              # 有哪些法源可查
python3 scripts/emit-citation-context.py              # 全站，筆記那一句與條文原文並排，寫進 _work/引用對照.txt
python3 scripts/emit-citation-context.py <檔案.md>    # 單檔，印到畫面
```

法名用「已知法源檔名」窮舉來配，不用泛用的「⋯⋯法」樣式——泛用樣式會把前面的字一起
吃進去（「各位都學過民法」整串被當成法名）。簡稱（憲法、納保法、稅稽法、遺贈稅法、
營業稅法、商會法）在 `ALIAS` 裡對到全名。「憲法」要對到「中華民國憲法」而不是
「憲法訴訟法」，所以比對順序是**結尾相符優先於含有**：中文法名的修飾語在前面。

`--scan` 只印條文開頭，不判斷對錯。條號存在但講的是別的東西，工具看不出來，要靠
讀那一行——民法第 721 條就是這樣抓到的。

## 工具的兩個缺陷（2026-08-09 修）

**條之N 從來沒有真的被驗過。** `article()` 的條號樣式寫成 `第\s*{art}(?:-{sub})?\s*條`，
那個問號讓「所得稅法第 4 條之 1」配到「第 4 條」——九十幾個帶「條之N」的引用，全部拿本條
的條文去對，看起來都對得上。已改成帶「之M」時只找 `第 N-M 條`；改完重掃，這批引用全部
對得上，也就是說筆記本身沒有錯，錯的是驗證。

**外國法的引用被當成我國法。** 法名樣式從「威瑪憲法第 134 條」「德國所得稅法第 23 條」
中間切開，拿我國憲法第 134 條（婦女當選名額）、我國所得稅法第 23 條（會計年度）去對，
必然對不上又報不出原因。已在 `cites()` 加 `FOREIGN` 前綴表跳過。查證後兩處的外國法條號
本身都是對的：威瑪憲法第 134 條確有依資力負擔公共負擔的規定，德國所得稅法第 23 條規範
私人出售交易所得。

**`--scan`／`--scan-all` 現在也跳過校訂註解。** 先前只有 `--names` 跳過，於是每改對一處，
報表就多一筆永遠命中的舊寫法；看久了會連真的錯誤一起略過。

**`cites()` 逐檔去重，同一檔裡重複的同一個錯誤只會列一次。** 對照表是拿來讀的，去重能省
一個數量級的篇幅，但改完一定要拿錯的寫法 `grep` 全站一次——憲法訴訟法第 55 條那一組就是
這樣才找齊三處的。

2026-07-29 首次全掃是 897 個引用、10 個對不上，那 10 筆到 08-09 全部處理完：
7 筆逕改（見下方已裁定表）、1 筆是法源檔放錯、1 筆是工具跨段誤配、2 筆原文如此。
引用總數變少是因為改掉的條號本來各自算一個相異引用。

## 法名核對（`--names`）

`--scan` 系列核的是條號。法名寫錯時條號往往是對的，而 `--scan` 拿錯的法名去找檔案、
找不到就當成「沒有這份法源」放過去——**空氣污染防治法那四處，全站掃了一輪都沒被攔下來**。

```bash
python3 scripts/lookup-article.py --names
```

比對表在 `lookup-article.py` 的 `MISNOMER`，發現一個加一條，每條要寫依據。
**不做通則**（例如把「防治」一律當成「防制」）：水污染防治法、傳染病防治法本來就是
「防治」，通則會把對的改成錯的。掃描範圍是成稿、週次筆記與 `docs/`；逐字稿初稿與 1121
的舊稿是原始材料，本倉不動它們，掃了只會一直紅。`<!--校訂 …-->` 註解整段跳過，因為那
裡本來就要照抄錯的寫法。

**本檔整份不掃**。這裡是登記錯法名的地方，已校訂表與底下的負向測試說明都必須寫出錯的那個
寫法，掃它等於永遠命中。代價是本檔的法名沒有機器把關，改本檔時自己注意。

2026-07-30 現況：21 頁、4 種登記在案的錯法名、0 命中。負向測試放一份寫著「稅捐徵收法」
的檔進成稿目錄會 exit 1 並指出行號，同一份檔的 `<!--校訂 …-->` 註解裡放「空氣污染防治法」
不會被算進去。

## 來源不全，跟內容有錯是兩件事

行政訴訟法那筆一開始被我當成「工具壞了或條號錯了」，查下去發現錯的是我拿來對照的
材料。**但 2026-07-29 記在這裡的診斷也是錯的**：那份檔不是行政訴訟法的節錄，是整份
放錯法規——`個別法源PDF/法律/行政訴訟法.pdf` 的內容第一行寫「法規名稱：(廢)國家總動員法
廢止日期：民國 93 年 01 月 07 日」，三十條全是國家總動員法。「收到第 32 條為止」是
國家總動員法只有 32 條，不是行政訴訟法被裁掉。

2026-08-09 從全國法規資料庫取得完整版（`FilesType.aspx?DataId=A0030154&md=m` 直接
回傳官方 PDF，62 頁、372 條，修正日期民國 111 年 06 月 22 日），放進
`個別法源PDF/法律/行政訴訟法.pdf`，重跑 `build-statute-text.py` 抽文字，該筆即對上：
第 256 條第 1 項「最高行政法院認上訴為有理由者，就該部分應廢棄原判決」，與
`課_四34_所得稅法四/W07_1016.md:906` 引的判決主文一致。放錯的那份移到
`_work/法源錯檔備份/`，沒有刪除；全站沒有任何一頁引用國家總動員法。

同時把 52 份法源文字檔的首行逐一比對過檔名，只有這一份對不上。做法是印出每份的
第一行與條數，一眼就看得出來——**檔名是誰放的，內容是誰決定的，兩者要各自核**。

這是「壞掉的時候仍然回傳合法值」那一類：查無此條長得跟條號寫錯一模一樣，照著改就會
把對的內容改壞。所以 `lookup-article.py` 查不到時一律附上「該檔收到第 N 條」，
看到「查無第 256 條（該檔收到第 32 條）」就知道要先去查來源。這個訊息當時確實把人
指向了來源，只是它報的是條數，報不出「這份根本是別部法」——**條數對不上會提醒，法規
放錯不會**。真正該問的第一個問題是「這份檔的第一行寫的是哪部法」。

工具**不猜**這份是節錄還是全文。試過用「最後一條是不是施行條文」判斷，兩個方向都會
錯：民法結尾是特留分（施行另有民法施行法）會被誤判成節錄，國家總動員法那份的結尾
剛好提到施行、會被誤判成全文。與其給一個會錯的判斷，不如給準確的事實讓人自己看。

## 跨段誤配

`行政執行法第23條第1項` 那筆是工具報錯，筆記沒有問題。
`課_二89_租稅法總論/W11_1111.md:524` 的小標是「### 執行期間如何接到行政執行法」，
下一段開頭寫「第23條第1項是徵收期間五年」——講的是稅捐稽徵法第 23 條，前後文都在講
徵收期間與核課期間。工具的法名與條號之間原本寫 `\s*`，而 `\s` 吃換行，於是段末的
法名跟下一段開頭的條號被接成同一個引用。

已改成只容半形與全形空格（`[ 　]*`）。法名在段末、條號在下一段，本來就不是同一個引用。

同一個形狀還會出現在小標結尾是法名、正文接著寫條號的地方，1140 的筆記是口述整理的，
小標常常就是一句話，這種排法不少。改完全站重掃，892 個引用沒有其他跨段誤配。
