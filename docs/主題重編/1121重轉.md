# 1121 舊稿重轉

1121（112 學年第 1 學期，2023 秋）的租稅法總論與租稅規避兩門課，成稿有 56 頁、45.6 萬字
（見下方〈順帶更正的兩個數字〉），但**整門沒有留下逐字稿初稿**。全站其他 108 頁都能跟
自己的初稿逐句比對算照抄率，這 56 頁只能改用口語殘留當代理指標，而那個指標量的是文字
風格，不是內容正確性（見 [校對盤點](校對盤點.md)）。

2026-08-09 裁定重轉，不是修舊稿。修舊稿改得動文字，改不出對照基準；重轉一次同時補上
基準，也給殘留最高的那 12 頁複看素材。

## 跑法

```bash
bash scripts/run-1121-batch.sh          # 前景，會佔住終端機十小時
( nohup bash scripts/run-1121-batch.sh >> _work/1121_轉寫/batch.log 2>&1 & )   # 這個
```

**一定要用後面那個寫法。** 整批要十小時上下，而 Claude Code 的 session 結束時會把它啟動的
子進程一起帶走——2026-08-09 第一次跑就是這樣停在第 10 檔，log 是空的、沒有任何錯誤訊息，
看起來跟「還在跑」一模一樣。啟動後用 `ps -eo pid,ppid,command | grep '[b]atch_transcribe'`
確認 ppid 是 1，才算真的脫離。

`run-1121-batch.sh` 把音檔清單、詞表、venv 都包好了，重跑幾次都安全（斷點續跑是
`batch_transcribe.py` 內建的：`.raw.txt` 已存在就跳過）。它底下呼叫的是：

```bash
source ~/Documents/NTU/1141/whisper/whisper-rt-full/whisper-realtime/.venv311/bin/activate
python3 scripts/batch_transcribe.py _work/1121_轉寫 "<稅法詞表>" <音檔...>
```

whisper.cpp 在 `~/Documents/whisper.cpp/`，模型 `ggml-large-v3-turbo-q5_0.bin` 加
silero VAD。實測約 15–20 倍速，85.1 小時推估 4–6 小時機器時間。輸出
`_work/1121_轉寫/<檔名>.raw.txt` 與 `.srt`，`_work/` 在 `.gitignore` 裡。

`scripts/batch_transcribe.py` 從 `1131_Taxation/engineering/tools/` 原樣複製，改了一處：
**逐字稿寫成之後就刪掉中間的 wav**。16k 單聲道每小時約 115 MB，85 小時要 9.8 GB，
而本機只剩 19 GB。`.srt` 留著，之後要對時間軸用得上。

斷點續跑是腳本內建的：`.raw.txt` 已存在就跳過，中斷了重跑同一行即可。

詞表照 1132 那條線的做法挑這兩門課真的會出現的詞（租稅法總論、租稅規避、稅捐規避、
實質課稅原則、量能課稅原則、租稅法律主義、稅捐主體、稅捐客體、納稅義務人、扣繳義務人、
稅捐稽徵法、所得稅法、遺產及贈與稅法、恣意禁止、稅捐中立性、經濟觀察法、脫法行為、
稅捐規避否認），不是全域詞頻前 N 名。whisper.cpp 的 `--prompt` 上限是 224 個 token。

## 驗收要驗內容量，不驗檔數

跑完數 `.raw.txt` 有幾份沒有意義——轉壞的檔照樣會產出一個 0 字的 `.raw.txt`，而下一次
重跑會把它當成已完成跳過。判準是每檔的「字數 ÷ 分鐘」，正常落在 263 上下（1132 那條線
從 W01 量出來的：24,055 字 ÷ 91.4 分）。掉出來的才是真的要重轉。

已知該是 0 字的只有那 6 個不到一分鐘的誤錄檔。

## 照抄率的結論在哪

`scripts/retention-1121.py` 產出 `_work/照抄率_1121.md`。**先看那份報告的校準節再看
數字**：`audit-proofreading.py` 定義的照抄率在這裡量不到東西——把 `_原稿/` 那 6 頁

與已校對的 40 頁（0.000–0.055）分不開。兩個模型對同一句話的斷句與用字幾乎不會一致，
指標被模型差異吃光了。

7 頁在灰帶、18 頁低於任何一份未編輯的逐字稿。這與 `校對盤點.md` 用口語殘留標出的 12 頁
